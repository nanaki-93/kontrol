Stop a worker when its caller leaves

Learn · Intermediate · 12 min · Context cancellation

Objective: Stop a worker cooperatively when its caller no longer needs the result.

Read-only reference · No responses are saved here.

Explanation

A Go context signals that work is no longer needed; it does not terminate a goroutine. The caller owns the cancel function and should invoke it when it no longer needs the result. A worker must observe ctx.Done() at blocking or repeated work boundaries and return promptly.

Worked example

A search handler derives a two-second timeout from r.Context(), defers cancel(), and passes the context into its worker. When the client disconnects, the worker observes ctx.Done() and returns after releasing resources it owns.

Exercise prompt (for reading)

A handler launches a goroutine that waits on a results channel before replying. The client can disconnect while the goroutine is waiting; no one then reads its result. Describe a cancellation-aware send and who calls cancel.

Reference material · Example response

Derive ctx, cancel := context.WithCancel(r.Context()) in the handler and defer cancel(). The worker selects between sending the result and receiving from ctx.Done(), then returns on cancellation.

Reference material · Self-check criteria
  • The handler owns cancel and calls it on exit.
  • The send selects against ctx.Done() to avoid waiting forever.
  • Cancellation is cooperative; the worker returns and cleans up.
