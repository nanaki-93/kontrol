## Context & boundaries

- **Primary scope:** `Kontrol/Features`, narrowly relevant `Kontrol/App/` integration, `KontrolTests/`, Xcode source registration when needed, and verification documentation. One app and one test target; no affected submodules.
- **Governing rules:** Root `AGENTS.md` is the only discovered agent instruction file. Its non-interactive validation policy applies to every task. Preserve keyboard and accessibility behavior through implementation and source review, but do not run hosted UI/presentation, AX, native keyboard/focus, screenshot or live-app checks. Never run unfiltered `make test` or `xcodebuild test`.
- **Starting-state prerequisite for Step 1:** Recheck HEAD, `git status --short`, staged/unstaged differences and root instructions before editing. Preserve unrelated changes, particularly existing Learning topic-publication fixes. Read the selected mocks and current tests before changing their assertions. If a schema, API, dependency or selector-algorithm change proves necessary, report the scope deviation rather than silently introducing it.
- **Implementation boundaries:** Transient feature-local preview and disclosure state only. Keep existing navigation/draft barriers, authoritative catalog and project inspections, completion/Undo verification, task and schedule stores, Focus service, News store and shared Settings owners. No preview-triggered IO or mutation.

For each step, run its focused non-GUI selector after a successful build as needed. Use an isolated derived-data directory, for example `/tmp/kontrol-ui-refining-derived`; add `-resultBundlePath` with a unique path when collecting test evidence. A zero-test run is not a pass. New test-suite names below are **deliverables**, not claims that those suites already exist. Register new Swift files in `Kontrol.xcodeproj/project.pbxproj`.
